# 已确认的数据库对齐工作流：1 → 6 → 5 → 7 → 8

## 范围与边界

用户明确选择顺序：编辑器/智能提示 → 查询分析/优化 → 导入导出/迁移 → 专用数据库工作区 → 数据库 AI 维护闭环。保留 Catio 外框、SSH/SFTP/隧道/MCP/Agent。必要依赖可补齐，但不自动扩展成整套结构编辑、备份管理或新引擎专项。

参考 DBX 固定版本 `046ae4cfb4a3a4675886b721ccad0b05c77d1ec1`；不是把所有增强功能都宣称为 DBX 已有能力。每个增量先核对参考实现，再 red/green、类型检查、真实驱动和前台浏览器验收，独立中文语义化提交。外部依赖不可用时明确保留门禁。

## 1. 编辑器与智能提示

- 外键关系保留来源/目标 namespace、源表范围内的 provider identity、1-based 列序和完整宽度。旧数据和无法确定分组的数据不猜成单列 JOIN。
- JOIN 来源限定当前语句/查询块；保持实际 defaultSchema、引用大小写、别名和同名表身份；复合键一个候选包含完整 AND 条件，不将不同约束合并。
- 已输入 JOIN/LEFT JOIN 时只替换目标前缀；ON 上下文只生成条件；字符串/注释/CTE 阴影不被当成物理来源。候选通过实际编辑器 guard/filter/接受键验收，而非只调用纯函数。
- 函数模板支持可跳转参数占位；复杂作用域、诊断、server version/SQL_MODE 与扩展逐项补齐。补全不是执行授权边界。

## 6. 查询分析与优化

- EXPLAIN、可视化、字段血缘与分析读取实际驱动结果和对象元数据。
- 区分不执行的 EXPLAIN 与会实际运行语句的 ANALYZE；禁止将写 SQL 当成只读分析重放。
- 引擎不支持/解析不完整如实展示，未知结构不编造。

## 5. 导入导出与迁移

- 分块/流式处理、跨页完整导出、类型旁路元数据一致；复杂类型与精度不能被字符串猜测替代。
- 大 SQL/文件任务有界资源、进度、真实取消和清理；不把取消/网络失败描述为已回滚。
- 写入结果未知先核验，不直接重放；一致性快照和可恢复任务需独立验证。

## 7. 专用数据库工作区

- MongoDB Extended JSON 文档编辑与主键/类型保真。
- Redis Stream/批量管理/大 key 有界读取。
- Elasticsearch 文档/索引管理与版本并发保护。
- DuckDB Parquet/CSV/JSON 文件工作流，Web 文件入口不接受任意服务器路径。

## 8. 数据库 AI 维护闭环

- 元数据按需、授权、必要范围，不默认向模型发送整库或凭据。
- 生成/解释/优化 → 预览/审批 → 应用工具执行 → 收据/状态核验，提示词不替代权限边界。
- 用户授权使用真实 DeepSeek 测试；凭据仅保留在临时测试进程内存，不写配置、日志、fixture 或 Git。固定夹具只证明传输，不冒充模型质量。
- 真实模型测试使用隔离对象和有界调用；记录脱敏的模型名、用量、实际结果和失败边界，不访问生产数据。
