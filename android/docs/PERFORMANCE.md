# 虫洞性能与相机验证

## 参考项目

- [libcimbar PERFORMANCE](https://github.com/sz3/libcimbar/blob/master/PERFORMANCE.md)：默认 B 模式参考约 106 KB/s，老款骁龙625、4线程；作者指出瓶颈常在相机。
- [cimbar-bigfile](https://github.com/peipei-labs/cimbar-bigfile)：改善大文件分片和调度，并没有证明其光学编码本身快于 CIMBAR；公开参考仍约 100 KB/s。
- [heliogram](https://github.com/ofitzharding/heliogram)：229.7 KB/s 来自 4K60 拍摄后电脑离线解码，不能当成手机实时净吞吐。其局部阈值和几何跟踪思路值得借鉴；该项目亦指出直接复用上一帧透视矩阵可能降低解码收益。本实现保留逐帧角点与透视计算，仅复用搜索区域。

本版本没有引入不兼容的新编码协议或把录像后离线解码包装成实时接收。仍用原版 Reed–Solomon / fountain / Zstd，保留去重后码流速度显示。

## 可复现的实拍验收

测试手机基线：用户提供 OnePlus 6，旧版本约 70 KB/s。测试文件使用 1–5 MiB 不可压缩随机文件，同时记录原文件 SHA-256；纯文本因压缩比高不适合直接比较。

1. 相同显示器、相同码图尺寸与亮度，分别使用旧/新 APK 各三次。
2. 正对、轻微倾斜（约15度）、近距离和远距离分别记录。从首次有效数据到文件保存完成计时。
3. 比较完整文件字节数/总耗时、接收页稳定速度、识别率及扫描丢失次数，不能只取瞬间峰值。再逐字节或 SHA-256 检查文件。
4. 缩放使用满足四角完整可见的最小倍率。高倍率裁切、过近超出镜头对焦范围、反光、低照度和滚动快门都可能降低速度。
5. 同时记录相机公开的帧率/缩放能力；API 暴露能力不代表每台手机的 HAL 都能稳定达到。

**状态：200 KB/s 实拍目标未验证。** 开发机没有连接 OnePlus 6；模拟器与合成透视图只验证软件和协议，不能证明实机自动对焦与吞吐。
